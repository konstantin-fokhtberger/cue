# Change specification: CI-001 pull-request quality gates

## Control

| Field           | Value                        |
| --------------- | ---------------------------- |
| Backlog ID      | CI-001                       |
| Requirement IDs | NFR-TEST-001, 002, 003       |
| Status          | implemented                  |
| Owner           | project maintainer           |
| Target revision | `ci/CI-001-pr-quality-gates` |

## Outcome

Every pull request and every push to `main` executes the accepted quality commands from a
locked dependency graph. A successful merge can therefore be conditioned on stable, named
checks rather than a developer's local assertion.

## Confirmed facts

- `TOOL-001` provides deterministic npm scripts and a committed lockfile.
- The target product is macOS arm64.
- GitHub-hosted `macos-15` currently uses Apple Silicon but is not the target M2 device.
- Target-device capture and TCC validation belongs to `CI-002`.

## Assumptions

- GitHub Actions is enabled for the repository.
- The public repository can use standard GitHub-hosted macOS arm64 runners.
- Unsigned packaging is sufficient for this pre-release CI gate.

## Scope

- Pull-request and `main` workflow triggers.
- Locked installation with Node.js 22.13.0 and `npm ci`.
- Full quality, coverage, mutation, production audit, and traceability validation.
- Unsigned macOS arm64 package verification.
- Least-privilege workflow permissions and commit-pinned first-party actions.

## Non-goals

- Self-hosted M2 runner.
- TCC permission automation.
- Signing, notarization, or release publication.
- Fixing inherited dependency advisories.

## Architecture and affected boundaries

- Components: GitHub Actions, npm quality scripts, traceability validator.
- Trust boundaries: pull-request source, third-party dependencies, GitHub-hosted runners.
- State transitions: no application runtime state changes.
- Data and retention: CI logs and generated local reports only; no user audio or transcript data.

## Alternatives considered

| Option                                       | Benefits                                     | Costs and risks                                               | Decision           |
| -------------------------------------------- | -------------------------------------------- | ------------------------------------------------------------- | ------------------ |
| Linux quality only                           | Lowest cost and latency                      | Cannot prove macOS packaging                                  | Rejected           |
| macOS for every check                        | Closest platform match                       | Higher cost and slower feedback                               | Rejected           |
| Linux quality plus dependent macOS packaging | Fast logic feedback and native package proof | Does not validate target hardware or TCC                      | Accepted           |
| Self-hosted target Mac now                   | Strongest platform evidence                  | Requires stable identity, provisioning, and runner operations | Deferred to CI-002 |

## Acceptance criteria

1. Pull requests and pushes to `main` run a stable check named `quality`.
2. `quality` installs exclusively from `package-lock.json` and runs `npm run quality:full`.
3. Traceability validation fails for missing, duplicate, extra, or incomplete P0/P1 rows.
4. A dependent `package-macos-arm64` check packages on an arm64 macOS runner.
5. Workflow permissions are read-only and first-party actions are pinned to immutable revisions.
6. The same quality commands pass locally.

## Failure modes

| Failure                         | Expected behavior            | Test ID                          |
| ------------------------------- | ---------------------------- | -------------------------------- |
| Lockfile drift                  | `npm ci` fails               | CI-LOCKFILE-001                  |
| Coverage or mutation regression | `quality` fails              | CI-COVERAGE-001, CI-MUTATION-001 |
| Missing traceability row        | Validator and `quality` fail | CI-TRACEABILITY-001              |
| Non-arm64 macOS runner          | Architecture assertion fails | CI-MAC-ARCH-001                  |
| Package regression              | macOS job fails              | CI-MAC-PACKAGE-001               |

## Security and privacy

- Inputs and trust: pull-request code is untrusted and receives only read-only repository access.
- Secrets: no secrets are exposed to the workflow.
- Provider/data boundary: no provider API is invoked.
- Logging and redaction: no audio, transcript, or credential data is used.

## Rollout

- Publish the branch and open a draft pull request.
- Observe both named checks.
- Require the checks on `main` only after GitHub has registered their contexts.

## Rollback

- Revert the CI-001 commit and remove the required-check configuration if the workflow is
  operationally unusable.
